# w5o: methodology, guidance and code review

> Amended October 28, 2026 following independent evaluation. This remains a review of the original w5o commit, not a statement of the repaired w5p state. Read the [correction addendum](../w5p_2026-10-28/REVIEW_CORRECTIONS.md) and [implementation ledger](../w5p_2026-10-28/CORRECTION_LEDGER.md) for corrected scope, source locators and repair evidence.

28 October 2026. Reviewed release **EU_SAE_520_w5o**, version **5.2.0-rc.6-wizard.5.15**, source commit **e5319826a1a8bc306c842b6a8745173045caf028**. The reference is Molina and Romero, *Comparable Small Area Estimates over Time*, manuscript dated 29 January 2025. The decision not to implement STFH is excluded as requested.

## Assessment

The core MFH covariance definitions and the joint-bootstrap change-MSE calculation follow the manuscript's statistical framework. Several extensions are mathematically reasonable and documented. However, **w5o does not follow every recommendation, the documentation is not fully consistent, and coding errors remain**. Documentation alone does not justify a statistical choice or demonstrate valid confidence intervals.

This review confirmed five groups of coding defects and a further qualification gap in exported MFH figures. Six documentation corrections are needed. None of the production code, current guidance files, saved configurations or existing analysis outputs was changed. The fixes below are recommendations, not completed repairs.

Detailed evidence is in [estimation review](estimation_review.md), [uncertainty review](uncertainty_review.md), and [guidance review](guidance_review.md). The latter contains baseline section/page locations and replacement wording, corrected by the linked addendum. Reproduction scripts and logs are under [checks](checks/).

## Coding findings

Findings 1–4 are **P2** under identifiable inputs/settings. Finding 5 is **P3**, a printed UFH step-log diagnostic error; it does not corrupt final estimate tables or reports.

| Finding | Trigger and verified consequence | Source and required repair |
|---|---|---|
| **1. Named matrix years are silently reassigned** | For R matrix objects from RDS/RData only, both benchmark-target readers and the shared population reader overwrite supplied year names. Ordinary CSV/Excel tables already match year columns by name. Target columns `2013=.30, 2012=.20` become `2012=.30, 2013=.20`. A two-domain population fixture changes a weighted mean from **0.14 to 0.46** by using the wrong year's populations. | [UFH target reader](../../../scripts/01_ufh.R#L678), [MFH target reader](../../../scripts/02_mfh.R#L2234), [population reader](../../../scripts/population_helpers.R#L117). Validate unique year labels and select columns by requested year. If unnamed matrices are allowed, document their positional convention separately. |
| **2. Duplicate target and population keys are silently accepted** | A target table with two entries for the same group/year, `.20` and `.90`, is accepted. Reversing the rows changes the selected target. The population reader also takes the first matching domain/year or domain row; sex/age-disaggregated populations are a realistic trigger. The domain-to-group check does not catch this separate issue. | [UFH long-table matching](../../../scripts/01_ufh.R#L713), [MFH long-table matching](../../../scripts/02_mfh.R#L2269); wide tables have the analogous problem. Require unique keys before `match()`, and reject conflicting values with a specific error. |
| **3. Identity UFH labels working variances as Direct MSE** | With identity transformation and `sm_all`, raw design variance **0.006250934** becomes **0.006750478** in `Direct_MSE`. The same issue applies to entries replaced under `sm_out` or direct-mode backfilling. Log runs restore raw Direct variance; identity runs do not. Main Comparison obtains raw Direct variance from MFH, so artifacts can disagree. | [Variance replacement](../../../scripts/01_ufh.R#L981), [log-only restoration](../../../scripts/01_ufh.R#L1078). Preserve raw Direct variance for every transformation and export the working variance separately. Smoothing the model input is legitimate; relabeling it without disclosure is the defect. |
| **4. A missing domain-year passes readiness but aborts MFH** | In a 24-domain fixture, one domain is absent in year two. Readiness returns estimates available and a warning; the actual MFH preprocessing then stops because GVF receives a missing sample size. The 23 complete domains never reach the later exclusion logic. | [MFH GVF construction](../../../scripts/02_mfh.R#L837), [sample-size rejection](../../../scripts/ufh_functions.R#L52). Either make complete two-year sampling a blocking readiness condition with affected IDs, or exclude unsupported cells before smoothing using an explicit documented policy. This does not require inventing nonsampled predictions. |
| **5. UFH benchmark diagnostics can show the wrong adjustment factor** | `build_mse_decomposition()` recalculates its target from `direct_povrate` rather than the target used for benchmarking. With external target 5 and model mean 2, the actual factor is **2.5**, but the diagnostic reports **1.5**. In log runs it combines logged direct means with currency-scale FH predictions: the fixture reports **0.5198604**, while the actual survey-target factor is **1.5**. | [Diagnostic aggregation](../../../scripts/01_ufh.R#L1257). Carry the actual applied target/factor from the benchmark operation into the diagnostics; keep numerator and denominator in the same reported units. Point estimates and bootstrap moments use the correct benchmark operation; this finding concerns the printed UFH step log only. |

**Additional output issue:** standalone MFH-stage significance plots use unqualified significance/95% interval labels even for boundary-sensitive fits; see [the plotting path](../../../scripts/02_mfh.R#L3265). The final Comparison plots and report do include warnings. Carry the same provisional qualification into each exported stage image so it survives sharing without its log.

**Lower-priority maintenance:** the shipped but currently unused `scripts/mcpe_functions.R::pbmcpeMFH2()` retains obsolete formula handling and a simulation/refit covariance mismatch. Current production dispatch uses the corrected shared engine. Remove/deprecate the old entry point or delegate it to the shared implementation; this is not evidence that the active bootstrap has the same defect.

## Deviations from Molina and Romero and whether they are justified

The distinction between a paper recommendation, an illustration, and an unspecified software choice matters. In particular, **LASSO is explicitly suggested by the paper**; using it is not itself a deviation. Likewise, implementing MCPE bootstrap responds to a development need explicitly identified on page 36.

| Topic | Difference from the manuscript | Assessment and justification needed |
|---|---|---|
| **MFH2 default** | Page 21 starts with MFH3 and a variance-homogeneity test. w5o defaults to MFH2; MFH3-first is optional with recorded fallback. | **Reasonable pragmatic departure, clearly disclosed.** Convergence problems justify a usable simpler starting point, not a conclusion that time-specific variances are equal. Preserve the actual selection/fallback reason and sensitivity checks. |
| **Pointwise primary significance across areas** | Page 37 recommends Bonferroni `alpha/D` for a family of D area tests and cautions against many-area hypothesis testing. w5o's primary colors/counts are pointwise; BH/Bonferroni are supplemental. | **Substantive reporting-policy departure.** Defensible for clearly exploratory or prespecified individual-area interpretation. It does not control false positives for the headline family. Specify the inferential family and primary rule before making familywide conclusions. BH targets a different error criterion and cannot fix invalid p-values. |
| **Variance smoothing** | Pages 10–12 allow smoothing unstable variances and illustrate full smoothing. `sm_out` instead replaces nonfinite or <0.001 variances. | **Disclosed but not generally validated.** The cutoff is application-specific and scale-dependent, particularly across currencies in identity welfare. Compare direct, selective and full smoothing for the intended survey. The name does not mean large-variance outliers are replaced. |
| **GVF retransformation** | The paper's example exponentiates fitted log variance; the code adds half the residual variance before exponentiation. | **Conditionally justified extra choice.** This is a conditional-mean correction under suitable Gaussian/homoscedastic log-GVF residual assumptions. The technical note describes it, but the paper-to-implementation mapping should list it explicitly; it is not universally unbiased. |
| **Common national sampling correlation** | Page 20 treats area design covariance matrices as inputs. `rho_sm_out` applies a national correlation to stabilized domain variances. | **Plausible stabilization with an additional common-correlation assumption.** Validate PSU identifiers, joint design and domain heterogeneity. The PSU adaptation should be distinguished from the matched-unit method in the separately cited literature. Reused PSUs alone do not establish covariance magnitude or sign. |
| **UFH transformations and EMDI implementation** | The paper's examples are mainly untransformed. w5o adds arcsine poverty and log arithmetic-mean welfare, using EMDI corrections. | **Reasonable extensions grounded in other literature, not prescribed by this manuscript.** Retain the documented EMDI arcsine integration discrepancy and transformed-domain limitations. Log UFH uses ML/Slud–Maiti; MFH's log correction is different. |
| **Log MFH prediction and percentage change** | Linear MFH does not prescribe the implemented currency-scale conditional-lognormal predictor or percentage-change delta interval. | **Mathematically motivated extensions.** `exp(eta+v/2)` is a conditional Gaussian-model calculation, not a universal finite-sample unbiasedness result. Percentage-change intervals add a delta approximation. Validate the intended outcome distribution. |
| **Joint MCPE bootstrap** | Page 36 gives the change-MSE identity and explicitly says bootstrap methodology/software needs development. | **Appropriate extension with coherent core implementation.** Annual MSE and MCPE use the same accepted draws and uncentered prediction-error products; inverse transformation and benchmarking are repeated within draws. Normal-quantile intervals are approximate, as the paper itself says. |
| **Conditional bootstrap scope** | The paper does not supply this complete implementation. The app holds selected formulas, sampling covariance, auxiliary values and populations fixed and refits the selected model type. | **Disclosed approximation with incomplete validation.** It omits variable/GVF/covariance-estimation uncertainty. Add explicit wording that it also does not repeat MFH3/MFH2 selection in each replicate. Repeatedly drawing until enough successful fits also requires checking failure rates and selection effects. |
| **Ratio benchmarking** | Not a developed component of the manuscript's illustrated workflow. w5o adjusts final estimates and repeats the adjustment in each draw. | **Coherent extension, subject to the input bugs above.** Survey targets are recomputed; uploaded targets are fixed and their uncertainty excluded. Matching totals does not establish coverage or preserve the [0,1] range. Validate the final benchmarked estimator. |
| **UFH/Direct period independence** | Dependent comparisons require cross-products/covariances. Separate UFH and Direct changes use zero cross-period covariance. | **Acceptable only when independence is supported or explicitly used as sensitivity analysis.** Separate annual model fitting does not make prediction errors independent. This is particularly consequential for overlapping survey rounds. |
| **Numerical refitting and covariance repair** | The paper uses standard package fits without this detailed acceptance/repair policy. | **Sensible numerical safeguards, transparently documented.** REML refits preserve the stated model. Input covariance repairs and the ±0.999999 correlation limit need audit and sensitivity; a valid endpoint does not establish interval coverage. |
| **Two-year product scope, direct means and covariate selection** | The paper treats general T, illustrates HT estimates, and suggests variable selection, preferably BIC. w5o uses exactly two years, design-weighted Hájek-type means, and configurable selection including default AIC in MFH. | **Mostly scope/implementation choices within the framework.** Document the exact algorithms and preference for AIC versus BIC; do not call Hájek or LASSO intrinsically inconsistent with the paper. |
| **Diagnostics and revision loop** | Pages 10 and 21 require checking assumptions/outliers and revising the model when necessary. The app produces diagnostics but does not enforce all substantive decisions. | **Human review remains required.** A successful computational run is not evidence that the paper's review/revision loop was completed. Keep run-specific decisions, sensitivities and reasons for accepting or withholding estimates. |

The key non-deviations checked are MFH1's diagonal random-effect covariance, MFH2's stationary AR(1) covariance with innovation/marginal variance distinguished, MFH3's initial variance fixed at one, and `MSE(change)=MSE1+MSE2−2MCPE`. Their current definitions agree with the manuscript.

## Guidance and instructions are not yet fully synchronized

The active guidelines, four technical notes, download instructions, three short guides and their Polish/Greek versions, READMEs, app help and QER notes were reviewed for methodological consistency. Translations received a focused check of methodological sections, not a full linguistic/layout certification.

| Required correction | Current contradiction | Where to repair |
|---|---|---|
| Retired `sm_out` rule | Standalone sampling note still says high variances are replaced. The guidelines explicitly supersede that description, so the departure is documented elsewhere but the note remains misleading. | Sampling-covariance technical note §8; also stale source comment in `02_mfh.R:888`. |
| Obsolete benchmark fallback | Guidelines say missing/near-zero aggregates cause factor 1. Current helpers reject nonfinite inputs and a zero aggregate with a nonzero target. | Guidelines §7.12, p52. Describe the actual failure/status behavior. |
| Unconditional nonnegative-rate guarantee | Ratio adjustment preserves nonnegativity only for nonnegative inputs and a nonnegative factor; allowed identity fits can be negative. Neither an upper bound of one nor correction of negative inputs is guaranteed. | MSE note Part I; guidelines §7.12. |
| Guaranteed positive covariance from repeated PSUs | The main guidelines elevate a persistent positive cluster-effect assumption into a universal claim. The companion note correctly qualifies sign and magnitude. | Guidelines §8.7, baseline p59, phrase “become positively correlated”; preserve the already conditional Annex G.8, baseline p130. |
| Understated multiplicity departure | Annex H and the alignment note say the paper merely warns, omitting its explicit Bonferroni recommendation and caution against testing many areas. | Guidelines Annex H; `docs/METHODOLOGY_ALIGNMENT.md`. |
| Stale person-row weighting | Sampling note gives unconditional household-size multiplication or the raw `weight` variable. w5o uses weight alone for person rows and weight × size for household rows. | Sampling-covariance note §§8 and 12 and 146. The main guides already give the correct distinction. |

Also add the GVF retransformation difference and selected-model conditioning to the deviation register; clarify the ML exception for log UFH in Annex H; and identify the automated LASSO screening sequence, rather than LASSO itself, as the package-specific choice. Exact replacement text is provided in [the guidance review](guidance_review.md).

For justified departures, maintain a single register containing: manuscript page/rule; implementation and source location; rationale and assumptions; supporting tests or simulation evidence; unresolved limitations; and the corresponding text in every active guide. For each real analysis, retain the input identifiers/design, chosen covariance/variance policy, actual formulas, model-selection outcome, boundary/repair diagnostics, bootstrap failures/precision, benchmark source and substantive diagnostic decisions. Existing metadata covers much of this, but it does not record or establish every analyst decision.

## Validation evidence and its limits

- A fresh isolated copy ran `tests/run_tests.R`: **275 lines labeled PASS, zero labeled FAIL**, and the suite completed. It also ran its methodology sub-suites, including installed MFH1/2/3 bootstrap checks and independent/oracle identities. These are reported check counts, not a claim of 275 independent statistical validations.
- The Word integration fixture was skipped because its rendering prerequisites were not detected in that process. No fresh full end-to-end production-country run or full report-render review was performed.
- All **46 dependencies** matched `dependencies.lock.csv`.
- The existing ZIP SHA-256 is `52d684f84b76fd87fa65e93deb838ca17ea6ea3b15a8e7b732a0cac1c734b4ef`. Independent verification confirmed its **185 manifest entries**, byte sizes and SHA-256 values, and the full **186-file** archive set including the manifest. Reviewed source files match the archive; the sole root-versus-archive difference is generated `docs/CLEAN_RELEASE_NOTICE.txt`.
- The existing extracted release directory contained startup-generated files, so its strict package verifier correctly rejected that used directory. A fresh extraction encountered an R/digest readability error on `.gitattributes`; independent Python verification of the archive provided the complete file/hash check instead. These verification-path limitations are not being reported as statistical code defects.
- Four bounded reproduction scripts exercise the actual target/population readers, actual UFH fitting and MFH preprocessing/readiness code, and the actual benchmark-diagnostic function. They use synthetic data and do not replace existing outputs.

The previously saved QER simulation results were reviewed, not regenerated. They include **2,100 MFH2 outer samples** under specified designs with known sampling covariances and fixed covariates. Reported nominal-95% absolute-change coverage is about **94.3–94.9%** in ordinary scenarios, **87.4%** in the low-signal scenario, and **65.2%** among its correlation-limit fits. These are scenario-specific findings; the latter two show why numerical convergence and more bootstrap draws cannot justify unqualified nominal-95% claims.

Coverage under actual complex survey designs, estimated GVFs/covariances, variable/model selection, final benchmarking and familywide testing remains unestablished. Larger fitted-model studies for MFH1/MFH3 remain outstanding. The review therefore supports neither a claim of no remaining bugs nor certification for official statistical inference.

## Suggested description for reviewers

> Apart from omitting STFH, the Workbench retains the UFH/MFH framework and change-MSE identity of Molina and Romero (2025), while making several explicit implementation and reporting choices. MFH2 is the default because of practical MFH3 convergence difficulties; the manuscript's MFH3-first sequence remains optional. The application adds transformed welfare/poverty models, stabilized sampling covariance inputs, numerical REML safeguards, a joint parametric MCPE bootstrap and optional reported-scale ratio benchmarking. These additions are conditional on their stated model/design assumptions and are not all prescribed or validated by the manuscript. The fixed variance threshold, common national sampling correlation, period-independent UFH/Direct comparisons and pointwise primary across-area significance require particular sensitivity review. Pointwise headline results depart from the manuscript's Bonferroni recommendation for a family of areas. Existing validation supports numerical coherence in tested settings but identifies important undercoverage near covariance boundaries and does not establish coverage for the complete survey-to-publication process. The code and documentation findings in this review must be resolved before describing w5o as fully aligned or free of known implementation errors.
