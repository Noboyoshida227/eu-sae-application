5.2.0-rc.6-wizard.5.15 - 2026-10-13

Pre-release w5o (EU_SAE_520_w5o) for the review meeting.

  • New name and guided set-up. The application is now called EU SAE Workbench (small area estimation of poverty and welfare). The guided version has seven steps: Input data, Map variables, Configure analysis, Configure model, Add AI assistant (optional), Review configuration and Run model. Required fields carry a red asterisk, the fields of each step are set out in up to three columns, the analysis years are chosen from the years found in the survey file, and the text is larger with darker headings. The classic dashboard keeps its layout and uses the new name and terms.
  • Front page. Two choices: New model run (default settings) and Load saved configuration (the last saved configuration, or a configuration file). The last configuration is no longer applied silently at start-up.
  • Model run configuration (formerly "dashboard setup"): Save configuration, Load configuration (last saved, or from a file) and Reset to defaults. Each run stores model_run_configuration.yml in its folder under app_runs/; it can be loaded later. A configuration file must contain an inputs section. After loading, the guided version opens Step 6, Review configuration.
  • Run progress and result. Step 7 (and the Status tab of the classic dashboard) shows the stages of the run with a progress bar, then the result, with buttons to open the report, the output folder or the run folder, and to view the configuration. The run log is in a collapsible section. Step 6 shows whether data readiness has been checked for the current configuration.
  • Guides and About. A Guides and notes menu opens the three guides (Guide 1, Install and start; Guide 2, Running the Workbench; Guide 3, Estimating poverty and welfare) in English, Polish and Greek, the download instructions, the guidelines note, the methodology mapping, the validation status and this changelog. About gives the version, the methods and where to find the licence notices. Logos placed in www/logos/ appear on the front page and in About; none are shipped yet.
  • Fix: survey unit. New setting Each row of the survey file is: a household / a person. With person rows, household size is not used and population_weight = weight. Before, a person-level file was weighted by weight × household size, so each person counted as many times as there are members in the household: population totals were inflated and large households were given too much weight in the direct estimates and in survey-based benchmark targets. An optional household ID lets the app check the rows: Data Readiness (Test 0f) reports the weighted population total and stops when the file has one row per person but "a household" is selected; the UFH and MFH steps apply the same check. Household-level files give the same results as before.
  • Fix: benchmark groups. With grouped benchmarking, each domain must belong to exactly one group in the analysis years. Data Readiness (Test 0g) and the UFH and MFH steps now stop with a message that names the domain, its groups, the years and the number of rows, instead of failing later with a technical error. Group membership is taken from the analysis years only.
  • Fix: loading a configuration restores the column mapping. When a configuration was loaded with its data files, the column lists were refreshed before the browser had applied the restored mapping, so fields such as domain, PSU and the join keys went back to their default names (in w5n this happened when the saved setup was applied at start-up; the readiness check then reported columns that were not in the file). The restored values are now kept until the browser confirms them.
  • Readiness after price changes. Changing how mean welfare is converted to constant prices (the price settings, the index values or the CPI file) now asks for a new data readiness check, like changes to the data, mapping, years and indicator.
  • Map legends for mean welfare show whole currency amounts with a thousands separator; the two-decimal labels ran together.
  • Significance plots in the report (final_report.html and .docx): a change whose pointwise 95% confidence interval excludes zero is drawn with a solid, thicker red interval line on top of the others (light grey); before, all intervals were faint. The domain order is kept. The caption and the report text state that the 95% intervals, BH and Bonferroni results are reported.
  • Documentation.
    • Three short guides in docs/instructions (PowerPoint and PDF, simulated example data): Guide 1, Install and start (10 slides); Guide 2, Running the Workbench (19 slides); Guide 3, Estimating poverty and welfare (21 slides; year-specific and anchored poverty lines and mean welfare, with results from runs on the simulated data), each in English, Polish (_PL) and Greek (_GR).   • Fix: in mean-welfare runs, a row where the MFH step fell back to the independence variance now also uses independence for its percentage change, and is flagged (scripts/03_comparison.R, .to_percent_change()). Before, the percentage change took a covariance implied by the step's change MSE; for these rows that MSE comes from the bootstrap MSEs, which need not equal the level MSEs, so a spurious covariance could be implied, and the final table showed no fallback and "covariance used". The change-and-RMSE box plots, change_rmse_by_method.csv and the "Change and RMSE" workbook sheets use the same rule (sae_change_rmse_by_method() in R/change_comparison.R), so their RMSEs match the percentage-change inference. For rows with a fallback, the percentage-change variance, interval, p-value and significance flags can change; because the BH adjustment works across domains, the BH p-values and flags of other domains can change too (their Bonferroni p-values do not, as the number of tested domains is unchanged), and so can the significance counts in the report and the Excel files.
